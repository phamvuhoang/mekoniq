# W07-T03 — Stocktake, waste and auditable adjustments

Status: verified_local (software only; SQLite restaurant lab). No scale, barcode scanner or photo storage is exercised.

## What was built

- `packages/domain/src/inventory/stocktake.ts`: `stocktakeAdjustment` / `applyAdjustment` (exactly the plan's functions) plus the commands:
  - `Stocktake.Open {stocktakeId, ingredientIds?}` freezes each ingredient's `onHand` and `movementSeq` — the ledger **checkpoint**.
  - `Stocktake.Count {…, ingredientId, counted, unit?, reasonCode?, evidence?, clockConfidence?, expectedVersion}`: stores the count and the **delta against the checkpoint**. Reason codes `waste | spoilage | count_correction` (anything else `REASON_CODE_INVALID`), optional evidence reference. Recounting replaces the number while open; the identical count again is a no-op; after approval counting is `STOCKTAKE_NOT_OPEN`. A count flagged `clockConfidence:'low'` or whose `recordedAt` and `occurredAt` differ by more than 5 minutes is `needsReview` (never last-write-wins on quantity).
  - `Stocktake.Approve {…, expectedVersion, acknowledgeReview?}`: approves the exact sheet version the approver saw (`VERSION_CONFLICT` when someone recounted meanwhile). With `inventory-policy/current.separateApproval` (default **true**) the opener and every counter are refused (`SELF_APPROVAL_FORBIDDEN`); reviewed counts need `acknowledgeReview` (`REVIEW_REQUIRED`).
  - `Stocktake.Apply {…, expectedVersion, ingredientIds?}`: appends one `adjustment` stock movement per counted item whose delta is non-zero and **adds the delta to the current balance** — a sale/receipt after the checkpoint is preserved, nothing is overwritten. Already-applied items are skipped, so an interrupted/partial apply is finished by running it again; the sheet becomes `applied` when every counted item is. A shortage that would push a `block` ingredient negative is refused whole (`INSUFFICIENT_STOCK`, nothing half-applied).
- `adjustment.ts`: a shortage leaves at the weighted average; a surplus has no purchase behind it, so it is valued at the current average and the movement carries `costEstimated:true` (`costKnown:false` when nothing was on hand). `valuation.ts` `stockValuation()` lists balance, value, average cost per base unit and `costKnown` — the data W07-T04 reports show explicitly instead of pricing gaps at zero.
- Permissions `inventory.count` (chef, manager) and `inventory.approve` (manager; owner `*`); feature `inventory` (`Open` new; the rest finish existing). Screen `Stocktake.ts` at `/stocktake` (Manage page).

## Limits

- "Stocktake from an imported (historical) count sheet" is not a separate path: an import can only create the same commands; no photo upload UI (the `evidence` field carries an asset reference only).
- Concurrent counters of different ingredients on one sheet serialise on the sheet version (the loser gets `VERSION_CONFLICT` and retries) — acceptable for a single coordinator; split sheets per area if that becomes noisy.
- Surplus valuation uses the current average (estimate); there is no purchase-cost lookup for surpluses.
