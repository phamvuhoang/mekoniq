# W08-T04 — Buffet, combo, weighed items and preset acceptance

Status: verified_local (software only; SQLite restaurant lab, Playwright against the fixture coordinator + tablet bundle). **No physical scale or scale protocol exists or is claimed.** Gate C: `docs/implementation/gates/C-restaurant-suite.md` (software-verified, not accepted).

## What was built

- Catalog models (`packages/domain/src/catalog/models.ts`, used by `Catalog.Publish` and the cloud relay mapper): an item may carry **one** of `weighed {unitMass,unit g|ml}` (price is per `unitMass`), `combo {components:[{itemId,quantity}]}` (components are existing plain items, no nesting) or `buffet {durationMinutes,extendMinutes,extendItemId}`; anything malformed is `INVALID_MODEL`.
- Pricing (`packages/domain/src/pricing/`):
  - `weighed.ts` `priceByMass` (the plan's integer function, half-up) and `weighedLine`: a weighed line is exactly one portion (`WEIGHED_QUANTITY_INVALID`), needs `measure {mass, source}` (`MEASURE_REQUIRED`, `INVALID_MASS`), and records mass, unit, unit mass, source and — for a keyed weight — `approvedBy`. `source:'scale'` is accepted **only** with a `scale` snapshot whose `validation` is `venue_approved` (`SCALE_NOT_CONFIGURED` otherwise: no pretend hardware); a keyed (`manual`) weight needs `weighed.manual` on top of the command's permission (manager) via `requiredPermissions`.
  - `combo.ts` `comboComponents`/`componentRefundMinor`: the combo line stores its parts with an exact share of the price and of the discount (largest remainder, both sums exact; zero list prices split evenly); refunding one part returns its share net of its discount. `quoteOrder` writes `components` and `measure` into the frozen line.
  - `buffet.ts` `Buffet.Start` / `Buffet.Extend` (the package and each extension are ordinary priced order lines via `placeOrder`; the `buffet` aggregate keeps the timer: planned end from the wall clock, extension from the old end while running and from now once expired; one active buffet per session) with **monotonic clock evidence** (`{bootId, monotonicMs}`): a different boot → `restarted`, a wall-clock jump > 2 min against the monotonic elapsed → `clock_skew`, none at start → `no_start_evidence`. Flags are shown to the manager; they never change price or time. `Combo.Quote` / `WeighedItem.Quote` run the same server-side quote for the named model only.
  - Sales report `units` now carry `basis` (`weighed | combo`; plain items carry none, so existing report consumers see no change) and, for weighed items, the measured `mass`.
- Presets (`packages/domain/src/policy/{presets,preset-acceptance}.ts`): new templates `cafe`, `table-service`, `buffet`, `chain` beside the unchanged `trial-service`, `cash-only`, `no-robot`, `robot-only`. They enable only the baseline groups of the capability matrix §3 (optional QR/loyalty/inventory/booking/robots stay for the venue to switch on). `IMPLEMENTED_FEATURES` lists the modules that exist end to end; `presetAcceptance` (dependencies hold, nothing unimplemented enabled, readiness-gated modules named, `deferred` = what the venue type needs but does not exist — `chain` ⇒ `chain`, `online`) and `presetMigrationPreview` (what would be enabled / drained / blocked; **never applied**, never enables a missing module). A unit test ties `IMPLEMENTED_FEATURES` to every feature a command is gated by.
- UI: cloud `FeatureSettings.tsx` lists all templates and shows the migration preview (enable / drain / "not available in this build"); tablet `ServiceModels.ts` at `/models` (active buffets with minutes left and clock flags, start/extend, weighed price by keyed mass, combo parts).
- Permissions/features: `Buffet.*` need `order.write` and feature `service.models` (+ `pos.order`); quotes need `catalog.read`/`catalog`; `weighed.manual` for the manager.

## Limits

- No scale hardware, protocol or calibration is built; the "scale" source is an approval gate waiting for a W10-style profile. Keyed weights are manager-approved, so a weighed counter needs a manager at hand until a scale profile exists.
- A combo's components ride the combo item's own kitchen ticket/station (the parts are snapshotted for stock, discount and refund, not split into separate tickets). Stock deduction for a combo uses the combo item's recipe unless the venue also publishes component recipes; the parts snapshot is there for that mapping.
- Buffet packages and extensions appear as order lines at their configured station (give them a non-kitchen station such as `wash`); there is no automatic table timer alarm — the screen shows time left and the manager decides.
- The cloud preview describes a change relative to the current *draft* in the editor; applying still goes through the existing publish/ack path.
- Preset template versioning (a "new version of cafe" migrating existing venues) is previewed by the same diff; no stored per-venue template version exists.
