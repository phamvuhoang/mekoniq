# W10-T06 — Vendor SDK adapters and optional Open-RMF / MassRobotics boundaries

Status: **blocked_external** — the vendor-SDK adapter framework (exact-version profiles, coverage matrix, native-goal reconciliation, epoch guard) and the read-only observation export are implemented and verified with an emulated SDK; no vendor SDK, licence, firmware or hardware was supplied, so no vendor adapter exists and the `vendor-sdk` profile stays `draft`.

## What was built

- `packages/robot-adapters/src/vendor/profile.ts`: `VendorProfile` (exact SDK + version + firmware, native command identity, licence/redistribution review, a per-operation coverage matrix `supported | unsupported | untested` where `supported` needs a conformance evidence reference), `vendorProfileProblems`, `VendorRegistry` (registers and resolves by the exact triple; no "compatible family").
- `packages/robot-adapters/src/vendor/sdk-adapter.ts`: `VendorSdkAdapter` — translates only `supported` operations (the rest: `UNSUPPORTED_OPERATION` / unacknowledged), completion only from the SDK for that native goal id (event or query), an SDK that cannot be asked leaves an in-flight goal `unknown`, a failed SDK call is `unknown`, stale control epoch / wrong robot / map / expired refused before the SDK is touched, `physicalStopConfirmed` always false, validation above `integration_tested` refused.
- `integrations/robot-observation/src/massrobotics.ts`: `massRoboticsObservationCapabilities()` (`commandMotion: false`), `observationFrom`, `ObservationSink` (publish only) — neutral field names, to be aligned with the official standard before a consumer is connected.
- `docs/integrations/rmf-boundary.md`: MEKONIQ as sole dispatcher, ownership mapping, what a future RMF use case must prove.
- `tests/adapters/vendor-profile.test.ts` (7 tests).

Cases: plan test (observation-only never advertises motion); profile rules (evidence for "supported", exact version, licence review, reconcilability) and exact-version registry; navigation with SDK goal id, idempotent re-execute, foreign goal events ignored, single completion; blind SDK ⇒ unknown, queryable SDK ⇒ truth, failed call ⇒ unknown; unsupported operations refused (cancel unknown, not "cancelled"); epoch / map / robot / expiry guards and no hardware claim; observation export read-only and the boundary document.

## Limits (why blocked_external)

- No vendor SDK, licence review, firmware or robot. The fake SDK is our model; nothing here is evidence about a vendor. A vendor adapter is registered per exact version after the common conformance suite (navigation, cancel, reboot, map, epoch) and a supervised run on its firmware.
- The conformance suite for vendor adapters is this file's emulated variant; a recorded-trace replay and a hardware run do not exist.
- MassRobotics field names are not aligned with the official standard; Open-RMF integration is not provided (documented boundary only).
