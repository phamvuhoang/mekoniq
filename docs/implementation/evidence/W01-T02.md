# W01-T02 — Keystore identity and wire signatures

Status: implemented and exercised on one Android API33 emulator; hardware-backed security is not inferred from the emulator.

The native P-256 key is non-exportable. Enrollment includes the native-generated epoch and certificate fingerprint in the signed challenge proof; a restart preserves the key/epoch. Public JWK and certificate information may cross the bridge. Arbitrary public `Identity.sign` was removed: enrollment, request proofs, journal signing, settlement closure and archive signing occur only in typed native paths. DER/JOSE conversion uses Nimbus, with 64-byte JOSE signatures and canonical base64url.

## Commands and observed results

- `... :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=io.mekoniq.tablet.DeviceIdentityTest`: 2 tests passed, including all five shared JCS vectors (Unicode, escaping, precise decimal strings and numeric formatting), key restart, raw signature length and tamper rejection.
- Installing the debug/test APKs on the dedicated emulator and invoking `adb ... am instrument ... DeviceIdentityTest` produced actual public Android signature vectors at `tests/fixtures/contracts/es256.json`. No private key was exported.
- Node 24 `node:crypto` and Python `cryptography` independently verified all five actual Android ES256 signatures in `tests/fixtures/contracts/es256.json` (5/5 each).
- Native canonical bytes match `tests/fixtures/contracts/canonical.json` byte-for-byte and hash-for-hash.

## Limits

The API33 emulator does not prove StrongBox, physical Keystore backing, hardware compromise resistance or a supported production tablet model. Physical keystore/enrollment acceptance remains separate. Signing golden vectors alone is not two-peer TLS qualification.
