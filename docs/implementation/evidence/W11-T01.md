# W11-T01 — Security qualification and sensitive data

Status: verified_local — hostile-input, tenant-isolation, session, payload, guest and release-bundle checks run against the real route registry, local PostgreSQL 17 (RLS, non-bypass role) and local Supabase Auth. This is **not** a penetration test and does not qualify a hosted deployment.

## What was built

- `tests/security/` (17 tests, `pnpm test:security`):
  - `tenant-escape.test.ts`: signed journal offered under another tenant is refused before any projection/inbox row; **every** registered route that names a venue (dozens, enumerated from the route table) refuses an owner of another tenant and leaks nothing; query/body-scoped routes (reports, assets, sync, chain) likewise; the pooled DB role has no BYPASSRLS, an unbound or forged context sees nothing, chain/channel/payment/invoice tables have forced RLS; organisation-scoped chain rows are invisible and unwritable across tenants.
  - `session.test.ts`: every protected route answers 401 with a code-only body to a missing, forged or **revoked** token; every mutating venue route refuses a cookie-authenticated request from a foreign origin (CSRF); error bodies never contain stack traces, SQL, URLs, secrets or JWTs.
  - `payload.test.ts`: each POST route returns 413 above its own body limit; duplicate keys, 5000-deep nesting, `__proto__` pollution and non-objects are refused without a 5xx and without polluting prototypes; oversized webhook bodies are refused before signature work and a bad signature never reaches the JSON parser; money fields reject floats/exponents/negatives/huge values.
  - `guest.test.ts`: guest endpoints reject forged tokens without leaking internals; staff/chain/automation routes are 401 anonymously; the web-checkout sandbox is closed by default.
  - `release-bundle.test.ts`: `scripts/release-security.mjs` finds planted service-role JWTs, database URLs, server-secret names, private keys and test-only seams (`X-Test-Actor`, `MEKONIQ_DEV_LAB`, `developmentTransport`) — and finds none in this build's public assets (`apps/cloud-web/.next/static`, `apps/tablet-web/dist`); the public anon key is allowed; lockfile → SBOM.
- `scripts/release-security.mjs` (scan + `--sbom`), `apps/cloud-web/src/server/modules/devices/scope.ts` (`validDeviceScope`, the plan's rule, kept as the single named predicate and unit-tested).
- `docs/operations/{secrets,access-retention,incident-response}.md`.

## Verification

```sh
source .superpowers/sdd/env.sh
pnpm test:security            # 5 files, 17 passed
node scripts/release-security.mjs   # exit 0 on the current build (run `pnpm build` first)
pnpm typecheck && pnpm lint   # clean
```

No defect was found by the sweeps (every route behaved); the value of this task is that the sweep now fails the day a new route forgets a scope, CSRF or limit check.
