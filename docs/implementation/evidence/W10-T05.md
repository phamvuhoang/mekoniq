# W10-T05 — VDA 5050 adapter with an explicit version

Status: **blocked_external** — a VDA 5050 **2.0.0** protocol adapter is implemented and passes a conformance suite against an in-memory broker and vehicle emulator; no vendor vehicle, factsheet, trace, official schema files or LAN broker exist here, so the profile stays an emulator profile (`integration_tested`).

## What was built

- `packages/robot-adapters/src/vda5050/`: `orders.ts` (builder + validator, `VDA_VERSION = '2.0.0'`), `state.ts` (validator, `currentOrderState`, `orderFinished`), `instant-actions.ts`, `connection.ts`, `adapter.ts` (`Vda5050Adapter`, the `RobotAdapter` implementation over a `Vda5050Transport` port).
- `tests/support/vda-rig.ts` (`createVdaRig`: in-memory broker + 2.0.0 vehicle emulator, `emulated: true`; other versions → `PREREQUISITE`), `tests/fixtures/vda5050/README.md` (provenance), `tests/adapters/vda5050-conformance.test.ts`, `docs/integrations/vda5050-support.md`.
- Catalog entry `vda5050-2.0.0` (robot-protocol, simulation, contract tested) from W10-T01.

## Verification

```sh
pnpm test:adapters -- tests/adapters/vda5050-conformance.test.ts   # 13 passed   (pnpm test:adapters: 41 passed with robot-dispatch and Valetudo)
```

Cases: plan test (an older update's state cannot complete the current mission; the right update does); version prerequisite and constructor guard; schema-valid order graph (even/odd sequence, current node start, max speed, not retained); strict completion conditions and silent duplicates; order update at the vehicle's node/sequence, stale or repeated update refused before sending, idempotent re-execute and conflict; vehicle refusal, unanswered order = unknown, publish failure = unknown, not connected = nothing sent; fatal error/failed action; cancel finished/failed/unanswered, stop = pause request never confirmed; duplicate / out-of-order / retained / foreign / wrong-version / malformed state counters; connection loss, reconnect, controller reboot, retained replay; vehicle isolation by topic and identity; no hardware claim; validators.

## Limits (why blocked_external)

- Emulator only: the 2.0.0 field list was written from the public specification by hand (no official schema vectors, no factsheet, no trace); the assumptions listed in `docs/integrations/vda5050-support.md` are unverified on any vehicle.
- No MQTT transport implementation (native executor) and no broker/ACL setup; `executor: 'native'` is declared, the native bridge is not part of this task.
- 3.x is not supported; only a failing prerequisite exists for it.
