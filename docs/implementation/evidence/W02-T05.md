# W02-T05 — Relay, private hints and bounded durable jobs

Status: implemented; local software checks below verified. External qualification limits remain explicit.

Implemented durable pending relay commands, venue receipts, operation/type/actor/device/version idempotency, command-specific permission checks, and owner fencing. Each pulled command carries cloud-signed delegation bound to its full hash, recipient ID/device epoch, current actor venue permissions and expiry. A revoked actor receives receipt-only reconciliation so a lost ACK cannot falsely reject an already accepted operation. Private Realtime hints are coalesced at a PostgreSQL boundary to one per five seconds per venue; periodic HTTP catch-up does not depend on receiving hints. Jobs use leases/SKIP LOCKED, a 20-job/20-second batch limit, durable results, reconciliation after recovered leases and bounded retry/dead-letter. Unknown external outcomes never trigger blind retries.

Changed: `server/modules/relay/*`, `server/jobs/*`, internal jobs route, sync effect/hint policies, migration `20261030000500_jobs_realtime.sql`, deployment job profiles and local `run-jobs.mjs`. Only hint publication and bounded orphan cleanup are enabled in the default handler registry; absent provider handlers remain unavailable.

Verified: historical effect firewall predicates; real PostgreSQL relay pending→venue acceptance and changed-command conflict; chef cannot relay Import.Apply; competing consumers claim each job once; expired sending lease reconciles; HMAC nonce replay rejected; concurrent publishers coalesce; real private Realtime accepts a member and rejects a foreign venue; Cron installation exists once and local wake succeeds without hosted secrets.

Limits: hosted Cron secrets/endpoint provisioning, provider effect conformance and release-scale load remain later gates. The scheduler is not used as a Free project keep-alive.
