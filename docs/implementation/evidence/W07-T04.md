# W07-T04 — Staff schedules, attendance and inventory/cost/attendance reports

Status: verified_local (software only; SQLite restaurant lab, `pnpm build` of the Next.js app). No time-clock hardware, biometric device or payroll system is involved — **this is not payroll**.

## What was built

- `packages/domain/src/workforce/`:
  - `schedule.ts` `Staff.Schedule {scheduleId,userId,startsAt,endsAt,stationId?}`: UTC instants (an overnight shift is one range; its business date is the venue-local day it starts), end after start and ≤ 24 h (`INVALID_RANGE`), no overlapping shifts for one person (`SCHEDULE_OVERLAP`, adjacent is fine), station must exist.
  - `attendance.ts` `attendanceDuration` (plan function, `NEGATIVE_DURATION`), `Staff.ClockIn` / `Staff.ClockOut {punchId,userId?,reason?}`: a punch is an **immutable source fact** keyed by (user, punchId) — the same punch from the outbox, a second device or a retry is a no-op; a different punch while one is open is `ALREADY_CLOCKED_IN`; `staff-clock/<user>` is the one-open-punch gate (racing punches: store CAS). Punching for someone else (explicit `userId`) needs `workforce.approve` (added in `requiredPermissions`) and a reason. Clock-out records its device; `deviceMismatch` is set when it differs from the clock-in device.
  - `approval.ts` `Staff.ApproveCorrection {attendanceId,clockInAt?,clockOutAt?,reason}`: a manager amendment stored as a separate `attendance-correction` (idempotent per content); the source punch is never edited; a manager cannot amend their own attendance; an amendment that makes the span negative is refused. `Staff.SetPermissions` is permissioned `identity.delegate` and always answers `IDENTITY_WORKFLOW_REQUIRED`: permissions/stations change only in the cloud identity workflow, so a kitchen actor gets `FORBIDDEN` and a manager gets an explicit pointer.
- `packages/domain/src/reporting/{stock,food-cost,attendance}.ts`, registered in `buildReport` / `REPORT_KINDS` / `REPORT_SOURCE_KINDS` — the existing tablet `Reports`, `lab.report` and cloud `GET /v1/reports/:kind` (+ CSV with formula-escaping) serve them with the same watermark/staleness rules (`unsynced` → every figure `null`, never 0):
  - `stock`: movements of the venue business date, current balances at weighted-average value, and a **ledger check per ingredient** (`onHand` vs Σ movements → `driftBase`; the fixture's opening balance shows `driftBase: 10000`, i.e. disclosed, not hidden).
  - `food-cost`: consumed cost (each consumption keeps its recipe version and the average cost it left at), prepared waste (already inside consumed), raw waste, count-adjustment loss, `missingCostLines`, `estimatedLines`, and `foodCostBasisPoints` only when there is a net-sales figure (else `null`).
  - `attendance`: rows by the day the punch started in venue time, amendments override beside the source times, lateness vs schedule, `open`, `noShows`, totals; `basis` states "not payroll".
- UI: tablet `Staff.ts` (`/staff`, main nav: clock in/out, attendance list with device flag, manager schedule form and correction approval, note that permissions live in the cloud identity workflow) and `InventoryReports.ts` (`/inventory-reports` under Manage: computed on the tablet, works offline, CSV, warnings for missing cost / unbacked balances); cloud `OperationsReports.tsx` + `/admin/operations` (reads `/v1/reports/*`, shows stale/unsynced states; read-only — venue actions go to the owner, tablets do not depend on it). `LanService.kt` lets cashier/kitchen roles read `staff-clock`/`attendance`.
- Permissions: `workforce.clock` (cashier, chef, manager), `workforce.write` / `workforce.approve` (manager).

## Limits

- Offline: clock-in/out, schedules and corrections are ordinary commands, so they work on any tablet with the coordinator on the LAN and queue like other commands; "offline grant revocation" is *not* implemented here — revoking a person's rights while a tablet is isolated remains the explicit W04/identity-grant pending state (this task does not change it).
- A staff member cannot *request* a correction in the app (the manager records it); there is no break/meal tracking, overtime or pay.
- The cloud report route was not given a new HTTP test: it is the generic `/v1/reports/:kind` route whose kind list gained three entries (build verified, behaviour covered through `lab.report`, which calls the same `buildReport`).
- Cost shown is only as good as the recorded movements: opening balances without a receipt have no value behind them (shown as unbacked in the ledger check).
