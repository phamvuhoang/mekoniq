# W10-T01 — Integration profile registry and evidence collection

Status: verified_local (schema, loader, rig shell and onboarding procedure). **No provider is selected and no provider document was available, so no real profile is enabled or approved.**

## What was built

- `integrations/profiles/profile.schema.json` (JSON Schema, `additionalProperties:false`) and `catalog.json`: one profile per provider / API version / protocol version / SDK. Fields: `kind` (payment, einvoice, channel, robot-protocol, vendor-sdk), `mode` (simulation / sandbox / production), `status` (draft → contract_tested → sandbox_verified → production_approved), `provider {name, docsUrl(https), apiVersion}`, `webhook {signatureScheme, signedFields, timestampToleranceSeconds, eventIdField}`, `idempotency {keyField, queryEndpoint}`, `credentialRefs` (names only), `version`, `adapter` (`path#export`), `requiredInputs`, `evidence {sandbox, production}` (ref + sha256 + date).
- `integrations/core/src/profile.ts`: `profileProblems` (structure + rules: a verified profile needs documentation, webhook/idempotency mapping for provider-called kinds, a version for protocols/SDKs, an adapter, the matching evidence; **a simulation profile can never be verified or approved**), `profileEligible` (plan function), `profileIsEligible`, `loadEnabledProfiles(catalog, 'release'|'sandbox')` (release = production-approved only; sandbox = also contract-tested simulation/sandbox profiles; a draft is never enabled).
- `tests/support/provider-rig.ts`: `createProviderRig(kind)` resolves an enabled profile of that kind and a registered simulator, counts calls, loads fixtures whose `{provenance, sha256}` must match their body (an edited "recording" is refused; unredacted ones too), marks the rig `emulated` unless the profile has sandbox evidence. **No profile or no simulator = failing `PREREQUISITE`, not a skipped test.** Per-kind simulators are registered by W10-T02/T03/T04.
- `catalog.json` ships the sandbox channel (simulation), the web checkout sandbox, and draft entries for Zalo, a delivery marketplace, a payment provider, an e-invoice provider, VDA 5050 2.0.0 (emulator) and a vendor SDK — each draft lists the exact inputs a person still has to supply.
- `docs/integrations/profile-onboarding.md`: the states and the six onboarding steps.
