# W10-T02 — Payment provider, VietQR and real-transaction reconciliation

Status: **blocked_external** — the provider-agnostic software is implemented and verified locally against our own emulator; no payment provider is selected, so no real transaction was ever reconciled and the `payment-provider` profile stays `draft` (disabled).

## What was built

- `integrations/payments/src/`: `provider-adapter.ts` (`PaymentProvider`: createIntent / query / refund / queryRefund; `verifyPaymentWebhook` — only the scheme we implemented, a profile naming another is refused), `reconciliation.ts` (`matchesPayment` plus `judge`: settle / unapplied / foreign / wait / close, `refundable`), `vietqr.ts` (payload builder + strict parser + CRC), `sim-provider.ts` (emulator with lost-response, 429 and refund faults).
- Migration `20261104000400_payment_intents.sql`: `payment_merchant` (venue ↔ merchant/payee binding set by `payment.operate`), `payment_intent` (status created/pending/captured/unapplied/failed/expired/unknown, refund ledger columns), `payment_provider_event` (event-id de-duplication), definer lookup `payment_intent_lookup` (our reference → tenant). Tenant RLS.
- Cloud `modules/payments/provider.ts` + routes `/v1/payments/:profileId/webhooks` (raw), `/v1/venues/:venueId/payments/{merchant,intents,intents/:id,intents/:id/refund,unapplied,reconcile}`; new relay source `provider:` (device `cloud-provider`, only `Payment.RecordProvider`, only `payment.capture`).
- Domain: `Payment.RecordProvider` — the terminal-capture rules (idempotent per external reference, applied up to the due, remainder unapplied, pending/unknown blocks) shared through `externalCapture`; method `provider` is refundable; permission `payment.capture` (held by no staff role).
- Test support: `tests/support/payment-rig.ts` registers the `payment` rig; fixtures `tests/fixtures/providers/payment-*.json` (provenance `emulated`, hashed); the test runner now has the `providers` and `load` suites.
- `docs/integrations/payment-acceptance.md`: behaviour, and what a real provider still has to prove.

## Limits (why blocked_external)

- No provider: nothing here has met a real API, real signatures, real retries or a merchant sandbox. `rig.emulated` is true everywhere.
- VietQR payloads follow the public layout; they have not been scanned by a bank app.
- The webhook-secret handling for a real profile reads the environment variable named in `credentialRefs`; no secret store integration beyond that.
