# W01-T03 — authenticated LAN and runtime health

Status: implemented and exercised over real native pinned TLS on two isolated API33 emulators. Physical network/device qualification remains required.

LAN uses a pinned TLS endpoint and scoped device-signed request proofs. The operator's one-use pairing offer and cloud-signed pairing grant bind device key, certificate fingerprint, actor permissions and station scope. Pairing nonces and request replay nonces are durable. Discovery never confers authorization. The queue is bounded to 100 requests with a five-second timeout; accepted responses are checked against a real committed operation receipt. The listener cannot create a replacement owner on timeout.

Heartbeat age uses Android monotonic time and a two-second TTL. Actual Activity resume/pause owns the foreground bit; a JS heartbeat cannot set it back to foreground. Background/suspended runtime, read-only storage and queue timeouts do not produce venue acceptance. Peer signed projections are cached in native SQLite; local dirty cash/grant/capture changes are preserved instead of overwritten. Signed source observations are merged only through explicit production ingest services.

## Commands and observed results

- `pnpm test:unit -- tests/unit/coordinator-health.test.ts`: observed behavioral RED (2 failures), then GREEN (2 passes), including stale/future/non-finite heartbeats and unwritable store.
- `... :app:testDebugUnitTest`: native queue heartbeat/suspend tests pass alongside SQLite tests.
- `ANDROID_HOME=... node scripts/two-emulator-lab.mjs --skip-build`: passed native cloud-signed pairing, real peer Session.Open/Order.Place through bundled production router, coordinator restart with one durable order/session, pinned-TLS retry with duplicate=true, and transport partition retaining pending/local intent. Cloud origin was unavailable. ADB forwards carry bytes only; no Node business listener is used. See `W01-two-emulator.json`.
- The initial owner force-stop alone did not prove sustained unavailability: Android restarted its device-owner process and genuinely accepted the command. The final partition test explicitly removes transport; it does not mislabel that as physical power loss.

The real two-emulator run first exposed an Android Keystore TLS `INCOMPATIBLE_DIGEST` failure. The key generated for domain ES256 had authorized SHA-256 only. [Android KeyGenParameterSpec.Builder documentation](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder) explains that TLS stacks prehash and require `DIGEST_NONE`. Newly created keys authorize NONE/SHA-256/SHA-384/SHA-512; typed domain signing remains SHA256withECDSA. Existing aliases are preserved. The disposable debug fixture explicitly reenrolls after resetting only its lab identity. Final harness evidence is recorded separately.

Signed native checkpoints use durable producer/cursor/effect state, expire after thirty seconds, and exchange through authenticated TLS without producing recursive business journal entries. Native cloud cursor/timestamp updates originate in HTTPS transport; a JS-supplied ACK without a previously verified native receipt is rejected.

The final clean Android instrumentation ran 6/6 tests, including actual Activity pause: a later JS heartbeat cannot revive a background coordinator. Paired checkpoint exchange remains implemented but was not exercised by the two-emulator journey.

## Limits

One Android emulator cannot prove AP isolation behavior, two-peer pairing, native coordinator loss on a second tablet, device Doze or 24-hour continuity. The lab runner fails prerequisites until two explicit test serials and signed pairing are supplied. Hardware profiles remain unavailable until W06; the local robot runtime only runs explicit simulated profiles.
