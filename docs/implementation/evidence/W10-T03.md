# W10-T03 — E-invoice and accounting export

Status: **blocked_external** — provider-agnostic issuing, querying, adjustment, venue recording, the tablet screen and the accounting export are implemented and verified locally against our own emulator; no provider is selected, so no invoice was issued to a real provider and the `einvoice-provider` profile stays `draft`.

## What was built

- `integrations/einvoice/src/`: `provider-adapter.ts` (`InvoiceProvider`: issue / query, optional amend / cancel), `issue-query.ts` (`nextInvoiceAction`, `afterQuery`, `requestKeyFor`), `amendment.ts` (`adjustmentAllowed`, `refundNeedsAmendment`), `sim-provider.ts` (emulator, faults: response lost, call dropped, 429, query failing).
- `integrations/accounting/src/export.ts`: schema `mekoniq-accounting-1`, lines per closed bill with invoice status, CSV with freshness header.
- Migration `20261104000500_invoice_requests.sql` (`invoice_request`, tenant RLS, unique `(profile_id, request_key)`), cloud `modules/invoices/issuer.ts` (collect / issue / reconcile / sweep / amend / list), `modules/accounting/export.ts`, routes under `/v1/venues/:venueId/{invoices,accounting}`.
- Domain `billing/invoice.ts`: `Invoice.Request`, `Invoice.Record` (relay-only, `invoice.record`), `Invoice.LinkExternal`; the provider relay source now also carries `Invoice.Record`. `Invoice.Request` checks that the `einvoice` module is enabled but **not** provider readiness (a request is a recorded wish that waits); `einvoice` stays out of `IMPLEMENTED_FEATURES`.
- Tablet: `screens/Invoices.ts` at `/invoices` (permission `invoice.request`, feature `einvoice`), request form with buyer fields, statuses worded as "requested — not issued yet / issued + lookup code / rejected + reason / external link"; `LanService.kt` lets the billing role read `invoice-request`.
- Test support: `tests/support/einvoice-rig.ts`, profile `sim-einvoice` (simulation) in the catalog.

Cases: plan test (lost response → queried, one issue call, one invoice, relay with the provider code); dropped call → still unknown → issueInvoice only queries → provider "not found" → draft → issued once; duplicate collect/issue → one row, one call, one answer; local invalid-totals rejection before the provider, 429 leaves draft; adjust/cancel permissions, idempotency, final cancel, never-issued refused, provider without the operation; refund-needs-amendment rules; lapsed relay resent then recorded; venue handlers (feature off, open bill, buyer validation, one per bill, issued needs id AND code, staff cannot declare issued, idempotent re-send, conflicting second invoice, adjust/cancel recording, external link ≠ issue); accounting lines, business-date zone, CSV neutralisation, completeness header.

## Limits (why blocked_external)

- No provider, sandbox account, certificate, legal confirmation or real schema; `rig.emulated` is true everywhere.
- One summary line per invoice (see `docs/integrations/einvoice-acceptance.md`); buyer validation is generic (tax-code shape), provider rules are per profile.
- The tablet screen was type-checked, linted and built with the bundle, not exercised in a browser or on a device; the cloud has no admin UI for invoices yet (API only).
- No sweeper job is scheduled for `reconcileInvoices` / `reconcilePaymentIntents`; they are callable (routes) and job-ready, like the other W09/W10 sweeps.
