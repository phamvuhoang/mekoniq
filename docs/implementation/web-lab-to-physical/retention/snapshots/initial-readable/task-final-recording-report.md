### Scheduling and authority design

The original full-action gateway reservation prevented HTTP pause/cancel from entering the existing fixed-step queue. Removing that reservation would have broken reviewed writer transfer, reclaim and resource ownership. The fix retains the same logical-run queue through complete action settlement and adds an internal, optional atomic `controlDuringStep` admission method only to fixed-step runners. Generic ScenarioRun implementations omit it and retain ordinary ordering, including the existing future-revision paced pause behavior.

A fixed-step request synchronously registers an ordered reservation token before the run-queue microtask. This closes a separately reproduced same-turn admission gap. A token becomes active and resolves readiness only when its original serial callback owns the run and has invoked runner.action. Pause/cancel can select only the oldest token for the same entry. They check current authority before waiting, again after readiness, and again at actual runner execution. They attach only if that same token is still active and first, with no await between this check and the runner's synchronous step-counter check/enqueue. If the runner already drained its batch, admission returns undefined and the control takes the ordinary run queue with exact revision checks.

Every token's outer finally clears active state, resolves readiness even when authority/runner admission throws, and removes only that token. A later queued step never replaces an older active/pending token. Controls waiting behind a transfer-before-step wake and refuse the former writer; a refused runner step still drains its independently valid control. There is no readiness/queue cycle: controls wait for step admission, the step never waits for a control's gateway queue position, and controls execute inside the runner rather than reserving a second lifecycle operation.

The original logical-run reservation still owns transfer, cold/live reclaim, archive, expiry and complete step settlement. Cold reclaim still resolves the current entry inside that reservation, holds through factory/hold/durable epoch/install, and remains view/reconcile-only. No world is created by the new path. Transfer cannot publish a writer/epoch while a prior admitted batch/control owns mutating work. Public close still stops new HTTP admission and waits admitted handlers before closing workers and releasing the data-root lease. A real public-close regression with a held fixed-step batch and admitted control verifies lease refusal until both settle and the worker closes; then the same root can be opened again.

The fixed-step queue now carries `beforeExecute` with each control. Each control still uses its own validation, revision, action hash, receipt and state checks; callbacks execute after asynchronous state reads and before effects. Priority cached receipts also check current authority at their queued execution boundary. Ordinary cached start/resume and generic runner retry semantics are unchanged; no readiness check was added to those cached paths. Private404, session/owner/current-entry/epoch, cookie CSRF, Origin and existing readiness/engineering-closure checks remain.

A denied/expired/stale control has no stopping effect on the already admitted batch. Once a control passes execution admission, the batch ends at that boundary even if checkpoint/worker work fails; uncertain mutation cannot be followed by additional ticks. A successful cached control returns its original receipt without reapplying pause/cancel or adding a control revision. The batch still yields at that boundary, preserving the old queue's behavior when a cached control was pending. A denied cached replay neither returns the receipt nor truncates the batch. Pending runner controls are capped at the existing 10,000 action-limit scale; durable receipt limits remain intact.

Runner controls are drained only between completed individual ticks, after a pacing wait, or in the step's existing finally drain. They cannot issue a mutating worker request alongside a tick request. Tick size, dt, unknown-ACK recovery, physical completion checks, receipt revisions and no-resend/no-respawn semantics are unchanged. Late controls are either drained by the step or explicitly take the ordinary queue; none are left pending without an owner.
