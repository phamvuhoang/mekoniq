This is a static dependency check for the final documentation handoff, not an executed launcher, fresh benchmark, or new qualification result. Read at the correction4 work stage; no product or service changes were made.

The ordinary Lab runtime check reads the installed content-addressed artifact and pin, then rechecks runtime bytes, manifest fields and schemas (`lab/scripts/runtime-artifact.mjs:120–134`, called by `scripts/check-source.mjs:3`). It does not compare the sibling Source Git HEAD to the pin. The portable launcher additionally verifies the actual Source tool tree against the pinned portable closure and declared Python locks (`scripts/start-irsim.mjs:78–91`); it does not substitute later Git metadata for byte verification. Contract sync `--check` explicitly allows the recorded generated-header commit to lag unrelated Source commits while verifying content hashes (`scripts/sync-engineering-contracts.mjs`, the `strip` and content-hash checks).

In contrast, `lab/scripts/production-build-identity.ts:5–10` requires both clean trees and `sourceHead === lock.sourceCommit`, and records the Lab HEAD plus exact production build file list/hash. A later documentation-only publication commit is therefore not the measured producer tuple, and should not be used as if it reproduces that measurement. A fresh capture must use the exact measured producer Source/Lab checkouts and their matching clean export/pin/build, or establish and record a genuinely new tuple. This is separate from the already-required exact historical L01 checker checkout.
