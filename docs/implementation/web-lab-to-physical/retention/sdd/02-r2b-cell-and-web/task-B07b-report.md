## Source API and admission binding (R64)

`ScenarioRun` adds optional `worldDisplay():Promise<WorldDisplay>` and `worldDisplayScene():Promise<WorldDisplayScene>`. Specific owner-scoped GETs are `/lab/v2/runs/:runId/world-display` and `/lab/v2/runs/:runId/world-display/scene`. Unsupported compositions return422 `WORLD_DISPLAY_UNSUPPORTED`; unknown/other-owner runs return404. Query parameters and arbitrary paths are rejected; GET consumes no caller-supplied command/body. Ownership/session/run identity is checked again after the serialized read, including reclaim/expiry races.

`WorldDisplay` is `{version:1,runId,revision,tick,simTimeNs,availability:'valid'|'stale'|'unknown',reason,snapshot:Sim3DSnapshotV1|null,control:CommittedWorldDisplayCommand|null,controlReason}`. Snapshot contains actual boot/scene identity. `CommittedWorldDisplayCommand` is only `Pick<WorldTickCommand,'targetTick'|'worldControl'|'velocities'>`. The successful durable tick captures this projection from the matching pending command before deleting pending; no H+1 ACK/current-next program can supply H control. H0 or legacy missing control returns `NOT_RECORDED_AT_TICK`. A failed next tick exposes only the prior committed H as stale with the Source terminal reason. A missing/mismatched committed snapshot is unknown and null. Each response is a fresh clone; no caller mutation reaches authority.

`WorldDisplayScene` is `{version:1,runId,availability:'available'|'unavailable',reason,scene:LabWorldSceneV1|null}`. Its one-time scene comes from the actual admitted live world closure, including immutable model/component digests, signed extent and arm base transform. Reopened context without that closure explicitly returns `WORLD_SCENE_UNAVAILABLE_AFTER_REOPEN`; latest fixtures/pending data are never used to reconstruct it. New reads inherit the existing admitted bounded scene/snapshot shapes; there are no raw asset payloads/history/new caller-sized inputs. One last committed control projection is checkpointed. Full snapshots/scene metadata are not added to RunView or per-action receipts. Existing snapshot retention, fsync, ACK ordering and recovery semantics stay intact.

The UI polls at most one world read at a time, owns its AbortController and run/generation checks, and loads immutable scene metadata once per run. If world H/revision differs from the current small Source view, it gets the owner-scoped Source view and draws only when identities/H/revision match. A later independent response cannot join newer telemetry/custody/attention to an older pose. Authority actions use current revision. Per R66, one wholly coherent old view/world pair may remain for≤500ms during a same-run/boot/scene next action, with original H/revision/age visible; histories/interpolation reset on revision. Run/boot/scene/replay switches clear immediately; failed/unknown physical authority discards current-valid pose. There is no extrapolation or history bridge.
