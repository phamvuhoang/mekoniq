### I4 — The capture reader confuses active measurement duration with the sum of RAF slices containing a draw

**Locations:** Source `scripts/browser-capture-clock.mjs:25`–`:34`; `tests/unit/browser-capture-clock.test.ts:12`–`:18`; Lab `scripts/measure-cell-production.ts:64`–`:69` and `:80`; adopted spec `docs/implementation/web-lab-to-physical/design/02-r2b-web-lab-spec.md:183`.

The spec separately requires at least three minutes of measurement after warm-up and display-frame p95 ≤ 33 ms. It does not require a fresh GPU draw on every display refresh. The producer samples each RAF, resets `lastDraw` each time, and sets `drawn` only when a draw occurred since the preceding RAF. Its `durationMet` uses elapsed and active-cell wall time. The reader instead requires both `activeCellMs` and `fullCellDrawingMs` to reach 180,000 ms; the latter adds only the immediately preceding RAF delta when the current sample has a draw. A valid rendered pose remains displayed during the intervening RAF slices, but those slices disappear from that accumulator.

**Analytical counterexample, not execution proof:** consider 185 seconds of genuinely advancing, full-cell draws every 20 ms on a 100 Hz display sampled every 10 ms. Actual draw p95 is 20 ms, within the 33 ms target. With samples at 10, 20, …, 185,000 ms, the reader's active accumulator is 184,990 ms while its draw-containing-slice accumulator is only 92,500 ms. The duration predicate rejects this otherwise sufficiently long active window solely because rendering occurs on alternate refreshes. A similar undercount occurs around 33 ms updates on approximately 16.7 ms RAF. This conclusion follows from the accumulator and producer sampling code; no application reader, fixture test or browser was executed for this review.

**Why Important:** the mandatory public reader can falsely refuse a spec-compliant capture and can encourage meaningless repeated draws as a way to satisfy duration. The actual candidate's 14,615.1 ms value must remain recorded as that reader's diagnostic, but it cannot establish that only 14.6 seconds of active world display occurred. Its independently measured slow cadence and pause remain genuine failures under I1. Neither finding cancels the other.

The complete fixture uses draws at every sampled interval; the no-draw negative sets all draws false. The slow-render test removes alternate render events while leaving the RAF draw stream unchanged. Those tests do not cover a coherent valid draw cadence lower than the RAF cadence.

**Required correction:** derive the required duration from a validated active moving-world wall window and verify actual render-stream coverage/progression separately, retaining the real draw p95, worker budget, pause bound and Source/clock/identity correlations. Do not simply trust summary fields, count frozen repainting as movement, substitute RAF cadence for actual drawing or loosen the stated thresholds.
