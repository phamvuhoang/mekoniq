# B05 shared MuJoCo world seam

Status: software simulation only, `accepted:false`, `not_calibrated`. B05 supplies the shared engine/factory/commit/evidence seams and a physical handoff rig. It does not publish a cell scenario. B06 owns journal-correlated giver/receiver receipts, withdrawal/custody policy, the served-two workflow and its fault matrix.

## Physical candidate

`coffee-delivery-world-v1` merges the original xArm 6 + Gripper G2 and mobile MJCF **before** creating one `MjModel`/`MjData`. The arm is at the map origin. The AMR base dock is `[0.35,0.48591366218667575,pi/2]`; its tray center stays at the B01 target. Source navigation bindings carry that base pose/heading, independently of the tray frame. The initial payload is empty; preallocated inactive cup slots are parked with contacts disabled. Each active cup retains one free-body identity, radius 0.04 m, height 0.1 m and mass 0.32 kg. Only the replaced static tray is removed; the nozzle stand and every mobile support/rail remain.

Original B01 dock yaw zero caused actual link4/chassis penetration (4.34 mm) at pick and link4/5/upper-tray penetration (up to 8.80 mm) on the old approach. This was a layout failure, not a universal infeasibility result. The frozen candidate rotates the AMR dock and adds horizontal placement approach and high transfer/withdrawal waypoints. Generated FK/IK vectors exactly match the frozen direct-rig vectors. The B00R conservative gripper-back/palm sweep remains unchanged (back 0.181 m, radius 0.06330284353802758 m). Sweep and actual contact evidence are separate.

The new world numerical policy is explicit: MuJoCo 3.17.0, implicitfast, elliptic cone, impratio 10, Newton/100 iterations/tolerance 1e-8, 10 × 2 ms substeps and exactly one 20 ms priming interval. Per-origin geom/pair contact parameters are made explicit before XML merging. Shared floor sliding friction 1.0 and mobile geom friction 0.6 use the engine's max mixing. This is **not** the B02a baseline mobile numerical lock; original arm/mobile profile files and compilers stay unchanged.

## Source-only interfaces and failure order

`WorldPortsFactory` receives manifest/run ID/directory, Source coffee state/context and boot-ID supplier. `mujocoWorldPorts(runtime)` supplies `WorldPlantBindings`: one `world`, AMR adapters, coffee ports, a committed snapshot getter, required `evidence` ports and optional independently admitted `metadata`/`navigation` bindings. These are TypeScript Source integration seams; no transport URL or Source callback is exposed on the browser/wire API. No public backend set is registered by B05.

`stepWorldOnce` executes prepare → one step → durable append → observation commit. The caller fsyncs the exact pending command before send. The factory separates arm command preparation (private cloned state) from actual joint/gripper/prop observation commit; coffee advances once and never steps physics. The world branch never constructs or advances `MockPlant`, emits mock arrival, or overwrites a mock motion result. Navigation adapters consume actual observations, with an explicit shared-world model descriptor.

A temporary target-tick timestamp is available while callbacks stage observations. Public clock/view advance only after commit and coffee staging succeed; durable business event draining follows. World context guards both `must`/`submit` and the existing direct `source.submit`/`source.store` paths against immediate persistence during commit. Failed commit restores the prior public coffee/robot state and stamp, retains the durable ACK/pending horizon, latches unknown and never drains staged events or resends physics. Lost ACK and append failure likewise stop permanently. Reload uses checkpointed observation/navigation identity, marks it stale/read-only and never refreshes it from a newer fixture or reopens a worker. A persistent world directory claim also prevents factory-level reopening after an interrupted create.

The process-wide `mujoco_engine` slot is shared with legacy arm/mobile runs. Same-run duplicate opens are refused too. Concurrent close calls await the same owned teardown; the slot is released only after `worker.close()` resolves. No other process is inspected or killed.

## Wire extension and lifecycle admission

The existing step payload gains optional `worldInteractions`: `{eventId,cupId,propId,kind:'birth'|'remove',targetTick}[]`. Absent/empty keeps legacy valid commands unchanged. Nonempty interactions are rejected in old arm/mobile modes before mutation. World mode requires a one-to-one match with `propPlacements`, admitted cup/prop binding, unique event/prop identity, exact target tick and legal lifecycle. Birth is confined to the declared nozzle placement region; removal requires an active cup. Grip/release/handoff/withdrawal never use a placement, weld or teleport. Adding an entry to a tray does not remove its physical cup; removal follows the source recipient-resolution intent.

Event IDs here identify Source-owned physical intents, not independently verified domain custody. Rig IDs start `rig:`. B06 must correlate production lifecycle/custody with real journal events; the presence of an event ID is insufficient proof. World release uses an explicit actual-support/relative-motion observation and a 25-tick window; it does not relabel one mobile contact as legacy `restingOn:'tray'`. World ports do not publish the mock physical cup ledger as custody evidence.

Optional world-only snapshot `worldStep` records native worker PID, one model, actual `nq/nv/nbody/ngeom`, accumulated physics substeps and priming count. Source verifies tick/clock/identity/model dimensions independently. Legacy snapshots omit this field unchanged.

## Complete-world evidence

`world-evidence-v1` records complete world snapshots plus the exact command and immutable observed lifecycle records in one ordered NDJSON stream. Each interaction carries event/cup/prop/kind/tick/command digest/reason and before/after map poses. Active prop admission is derived from the admitted scene and recorded interactions; it is never inferred from an ACK. The existing fixed-load mobile admission remains strict and unchanged. World validation reuses it with the exact lifecycle-derived active set and independently admitted arm/mobile/contact identities.

ACK append fsyncs a bounded WAL before logical commit. Published gzip chunks are immutable and hashed; write intents, unpublished tails, missing/corrupt records, gaps and identity mismatches make readback incomplete. The existing caps remain 256 KiB/line, 16 MiB stored and 64 MiB inflated/chunk, 100 MiB stored/run stream, 400 MiB total inflated, and 30,000 intervals. Writer flushes at 250 rows or 12 MiB inflated. Shared B03 durable publication and bounded-file/path/size guards are reused; mobile evidence bytes/read behavior remain unchanged.

Free-joint and matrix-derived representations of the same pose use the named world-only `WORLD_POSE_CONSISTENCY_TOLERANCE=1e-10`, including quaternion sign equivalence. Finite/unit checks remain; raw values are never changed. Initial representative runs stopped at birth tick 101 because an exact quaternion-byte comparison rejected ~6e-16 roundoff. Their raw rejected ACK and explicit gap remain under `/tmp/mekoniq-b05-worker-rig-{1,2}`; the correction is validation consistency, not physics tuning.

Raw tick zero includes priming; interval metrics cover `(0,lastTick]`. Instantaneous support/grip phases are physical observations, not business custody. The direct rig's raw per-substep contact-point archives are separate from the runtime's complete snapshot/contact-aggregate stream and its budgets.

## Evidence inventory and scope

The versioned [B05 evidence index](mujoco-world-rig/b05/campaign-integrity.json) preserves direct trial hashes, and [frozen policy](mujoco-world-rig/b05/candidate-01-policy.json) records all ten nozzle-birth XY offsets, motion/oracle policy and input hashes. Direct raw gzip files remain at `/tmp/mekoniq-b05-probe/trial-{1..10}.ndjson.gz` (about 27 MB each); each has 2,503 rows, 2,502 intervals and 25,030 actual substeps, all finite/clock-valid. All ten passed. The frozen direct scripts are retained byte-identically, including their original local paths, for provenance.

The [production comparison](mujoco-world-rig/b05/production-comparison.json) inspects shared model arrays and existing traces. Shared body/geom/actuator parameters, solver options and waypoint vectors match in the inspected fields. Models are not bit-identical: direct rig has one cup slot (`nq=28,nv=26`); production has two (`nq=35,nv=32`), with the second inactive. First cup-position divergence occurs at tick 103, before grip (~0.97 µm); max cup component difference is 91.31 µm. Do not uniquely attribute accumulated drift without an isolating experiment. Direct `cupInTrayM` uses tray body origin; runtime `poseInSupport` uses `[0,0,0.01]` in that body, explaining the 10 mm Z offset.

The first representative production IPC rig (`/tmp/mekoniq-b05-worker-rig-3`) passed: 150 receiver-window ticks, zero forbidden arm/mobile contacts, 1.00781155 m transport and 3.950912 mm maximum per-tick cup translation. It recorded 2,503 complete rows, 2,525,076 stored bytes, 27,457,940 inflated bytes, 11,577 bytes maximum record line and 2,847,820 bytes maximum inflated chunk. It predates the additive native-counter field. The final production two-slot ten-offset campaign and its frozen source/config identity are recorded in the B05 report and versioned production campaign inventory.

The final production campaign passed **10/10** with the same declared offsets and two-slot native model. See [production policy](mujoco-world-rig/b05/production-policy.json) and [inventory](mujoco-world-rig/b05/production-campaign-integrity.json): 10 distinct worker boots, 25,030 complete rows, 250,300 observed substeps, all receiver windows150 ticks, forbidden arm/mobile contacts0.
