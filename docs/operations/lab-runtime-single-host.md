# Single-host persistent Lab runtime

This is a simulation-only deployment package. Source owns mission, journal and custody; Lab remains simulation/replay. No device, Docker socket, ROS, Webots or hardware provider is mounted or enabled. Dynamics remain `not_calibrated`; generated candidates remain `accepted:false`. Public HTTPS, Cloud Run and native amd64 are unqualified until their own assigned deployment and execution evidence exist.

## Before deployment

Build from a clean Source commit with Node 24.22.2/pnpm 10.32.1 using `deploy/lab-runtime/build.sh IMAGE --platform linux/arm64` (or the actual host architecture). The immutable image contains the bundled runtime, schema closure, full committed MuJoCo tool/fixture/license closure, hash-locked Python 3.11 environment and generated Serve mobile catalog. Portable-only engineering registers `engineering-mujoco-3d-v1`; native profiles return `PROFILE_COMPILER_UNAVAILABLE`. It does not install native compiler helpers or PyYAML and does not advertise them as available. Arm and single-world cell use registered server fixtures. `health.engineeringCompilerProfiles`, installed/enabled backends, sourceCommit, schemaHash and OCI revision must match the intended build.

Assign a Linux host with a local filesystem. NFS, distributed filesystems, shared multi-host storage and rolling replicas are unsupported. Set immutable `LAB_RUNTIME_IMAGE` and trusted nginx `LAB_PROXY_IMAGE` digest references, exact `LAB_PUBLIC_HOST` (normally a hostname without a port for HTTPS 443), exact `LAB_ALLOW_ORIGIN` (`https://…`, no wildcard/path), and a random `MEKONIQ_LAB_ACCESS_KEY` of at least 32 characters in the operator's secret environment. Never put credentials in command arguments, URLs, query strings, browser localStorage, run archives or Git. Provide TLS full chain/private key as read-only files readable by proxy uid 101. The profile requires no paid provisioning automatically.

From `deploy/lab-runtime/single-host`, run `docker compose config --quiet`. Once the assigned external deployment is authorized, `docker compose up -d` starts one runtime and its TLS proxy. The runtime is uid 1000, read-only except `/tmp` and the local named volume at `/data/runs`. The image pre-owns `/data/runs` for uid 1000. For a bind mount, provision that directory's ownership and write access beforehand. Do not share it with another service or change/unlink files while a runtime owns it.

## Ownership and API

`LAB_DATA_DIR` defaults to `/tmp/runs` in the image; the persistent profile sets `/data/runs`. The runtime validates directory and write access, then holds an exclusive SQLite write transaction on `.runtime-owner.sqlite` before provider setup or HTTP admission. A second process/container fails `LAB_DATA_DIR_BUSY`; corrupt/uncertain ownership state fails closed. The lock file is permanent; never remove it to force startup. The kernel releases the transaction when its process dies. This process lease is separate from run authority and source journal transactions.

Pair via `POST /lab/v2/sessions` with the access key; keep the bearer token in application memory. The response's public `sessionId` is an independent UUID, not the bearer/cookie secret. Session IDs are not discoverable through a listing API. Local cookie sessions keep HttpOnly, SameSite=Strict, Path=/lab/v2 and CSRF validation; mutations also require an allowed Origin. Bearer queries are refused.

A new run returns `writer: {runId,sessionId,controlEpoch:0}`. Unrelated sessions see private 404. Its current writer may POST `/lab/v2/runs/:runId/writer` with `{operation:"grant_read",recipientSessionId,controlEpoch}` to authorize that active paired recipient for run snapshots/report/SSE/display/indexed downloads. Granted readers cannot export, delete, archive, transfer, reconcile or move the run. `operation:"transfer"` explicitly changes the writer and increments the epoch; previous authorized readers retain reads. The recipient must already be paired, and the operation executes in the run mutation queue.

After a transfer every writer mutation carries `X-Lab-Control-Epoch` equal to the current epoch (writer-management operations instead carry `controlEpoch` in their JSON). Only the original epoch-0 writer can omit the header. Supplied stale epochs always fail `RUN_WRITER_CONFLICT`. Actions and transfer serialize with execution-time authorization/expiry checks; streams and report reconstruction do not reserve that mutation queue. There is no disconnect, expiry or key-holder takeover. Expiry closes the current owner's run when cleanup occurs; the former creator's expiry cannot close a transferred run. Re-pairing needs an explicit transfer from a still-valid writer, or the saved proof for view/reconcile recovery.

The reclaim proof restores only view/reconcile access and existing proof-owner export/delete/archive housekeeping. It revokes former readers/writer, persists a fencing epoch and cannot transfer or resume physics. Create a new run for new motion. Epoch metadata contains no credential. A failed durable fencing operation is a refusal; inspect/re-pair/reclaim rather than retrying motion blindly.

## Health, stop and recovery

Check `/lab/v2/health` through the exact allowed Host. It reports identity and configured capabilities, not scenario readiness. Pair and POST `/lab/v2/readiness` with the actual scenario/backend and project or admitted engineeringRef; verify `canStart` before creating a run. The TLS proxy disables response buffering, sets explicit connect/body/send/SSE timeouts and forwards only its configured Host. Reject wrong Host/Origin in the deployed smoke; exercise a live SSE stream and stop/action separately.

For a planned stop, stop submitting new runs/actions, save reclaim proofs privately, export required evidence, then `docker compose stop runtime`. Public gateway close first stops request admission, aborts owned HTTP responses/captures and waits for admitted IO (including SSE journal reads), then closes workers before releasing data-root ownership. The profile allows 60 seconds. If the grace deadline is exceeded, Docker may kill the container: that is a crash, never a clean-stop claim. Do not start a replacement until the old container has exited. The proxy alone cannot transfer writer ownership.

For key rotation, drain/stop, change the secret environment and recreate the runtime using the same image/volume. Old in-memory sessions are invalid; re-pair with the new key. Saved runs require their proof to regain view/reconcile. The key is not a motion takeover credential. Confirm the old key is refused and the new key pairs; avoid printing either credential in diagnostics.

After a crash, keep the volume unchanged. Restart the same pinned image with the same schema/source identity; a mismatched pin refuses reclaim. Committed chunks/journals remain readable; unfinished actions may be unknown/interrupted and require reconciliation. Reclaim requires an existing identity-validated checkpoint. Cold arm recovery retains the old arm state/scene bytes, reports `RECLAIM_PLANT_UNAVAILABLE` and stale retained poses, and produces no new physical telemetry; its unavailable live arm report is not a new measurement. Reclaim never restores `mjData` or resumes a world from a workflow checkpoint. Finished saved runs may be exported again from retained evidence. Unknown replay staging directories deliberately block new exports (`REPLAY_RECOVERY_REQUIRED`); do not delete/adopt them automatically. Preserve a verified offline copy, inspect its identities/hashes, and perform any disposition as a separate operator recovery action.

For backup/export, stop the runtime and confirm exit first, then make an offline copy of the entire named volume (journals, checkpoints, engineering bundles, evidence, reclaim metadata and ownership database together). Keep original raw archives untouched. Hash the copy before opening copied SQLite or evidence readers. The copy contains private reclaim proofs as hashes and internal authorization metadata; store it with controlled access. The HTTP replay package is sanitized display/replay evidence, not a full recovery backup. Restore only into an isolated local volume under the matching pinned image; keep all motion disabled until explicit new-run admission.

## Bench evidence after idle expiry or restart

A bench holds one MuJoCo worker from start until termination. Its host inactivity lease defaults to 60,000 ms. Operators can set a positive integer duration using `MEKONIQ_BENCH_IDLE_MS`. Startup and each acknowledged control tick renew it. Reads, duplicate actions, pause and resume leave the deadline unchanged. After expiry, the run enters `needs_attention` with `BENCH_IDLE_EXPIRED` at the last confirmed tick. The runtime closes the worker, releases its slot and flushes the trace. The run report exposes the configured duration and expiry reason. A new run must pass admission to move the simulated plant again.

Keep the persistent data root on an operator-sized volume with a capacity limit. Each bench has a 16 MiB compressed trace budget plus its bundle and metadata. Closed and archived benches accumulate on disk. Monitor free bytes and suspend new admissions while making room if the volume approaches capacity. The idle lease and the gateway's open-run limit do not reclaim disk. Retention and disposal are operator decisions after verifying a backup.

For cold review, use the offline volume-copy procedure above. Match the saved run ID to the `runId` in the run directory's `reclaim.json`. Keep the entire directory, including `bundle/`, `trace/manifest.json`, and the named chunks. Use the matching source revision's `readBenchTrace` on the copy, with the expected run ID, axes and plant/drive/profile digests from the saved report and its last confirmed tick. It verifies bounded chunk reads and returns explicit issues and null samples for unverified data. If an orphan has no saved report, use its `reclaim.json` run ID and `input.bench` request with the matching pinned provider's `benchPlant` to obtain the expected axes, plant digest and drive digest. The submitted control profile supplies the profile digest. Use the manifest's durable last tick (0–500) for a review of that prefix. Empty coverage (`lastTick = -1`) means that no tick reached disk. Compare the manifest SHA-256 with the saved result when available. New wheel chunks retain the end-of-tick chassis forward speed beside the angular samples. Older chunks without this observation have no body comparison. A report saved before shutdown also preserves the terminal result. Without an independent report or manifest digest, document that provenance limit. A bench has no cold execution checkpoint. Cold reclaim returns `RECOVERY_CHECKPOINT_MISSING`; review never requires replaying a command.

## Qualification limits

`tests/security/lab-run-writer.test.ts` uses real HTTP clients with a protocol double; its engine-step count proves authority, not physics. `lab-runtime-persistent.test.ts` distinguishes local OS-process/mock crash recovery from an actual Mac portable worker shutdown. `lab-runtime-container.test.ts` covers actual mobile compile/readiness/run, arm/cell execution, named-volume exclusion, kill/reopen, committed chunks and finished replay only when a clean image and responsive Docker are supplied. A skipped suite is `not_run`. Linux arm64 inside a Mac VM is not native amd64. Record image ID, source/runtime/schema identities, architecture, all failed attempts and owned cleanup; do not modify historical G-CLOUD1 or commissioning evidence.
